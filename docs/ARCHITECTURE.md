# Architecture & app contract

The simulator is a zero-dependency browser app (`public/`) served by `server.js` (static files + `/api/llm` OpenRouter proxy + `/api/site` page fetcher). Game state is one JSON object persisted in IndexedDB. Time advances in whole days.

## Principles

1. **Practice the real skill.** Each tool should look and behave like the tool a real founder uses in 2026 (Mercury, Stripe, HubSpot/Attio, Instantly/Smartlead, Meta Ads Manager, Linear, Carta, Gusto/Deel, Clerky…). The player does the actual work: writes the actual email, the actual feature spec, the actual pitch, picks the actual budget.
2. **Real inputs where possible.** Real prospects (manual or CSV), real websites (fetched via `/api/site`), the player's real LinkedIn/bio/deck (uploaded files), real copy. AI personas judge them.
3. **Realistic numbers.** Use `docs/research/*.md` (sourced 2025–2026 benchmarks). Shared numbers live in `public/core/params.js`; app-specific numbers go at the top of the app module with a source comment. Never present a `[design]`/`[A]` assumption to players as a real statistic.
4. **Time costs.** Every player action costs founder hours via `ctx.act(fn, { hours, label })`. Use realistic durations (writing a personalized cold email ≈ 6–10 min, a discovery call ≈ 45 min, a feature spec ≈ 30–60 min, etc.).
5. **2026, not 2016.** AI agents, AI SDRs, AI coding agents, AI search, Meta Advantage+, Stripe Billing, post-money SAFEs, solo founders, micro-SaaS. Call out outdated playbooks in UI copy where relevant.
6. **LLM = judgment, statistics = scale.** Use LLM personas for judging quality (an email, a page, a feature, a pitch, a call) on a *sample*; use the statistical model for volume. LLM output must be calibrated against real base rates (e.g. most cold emails get no reply — gate with deliverability/attention probabilities first, then let the persona decide).
7. **Operator quality must show, in every function.** Every business function and system (sales, marketing, product, support, success, finance, accounting, legal, hiring, fundraising, pricing, partnerships, ops, even calendar and inbox) must clearly separate a *stellar*, *good*, *average* and *mediocre* operator, with outcomes as realistic as the research allows. Quality comes from what the player actually does: the specificity of the email, the questions on the call, the spec, which metrics they watch, timing, follow-through, what they choose not to do. It never comes from a difficulty setting or clicking more. Each function needs (a) inputs that real skill changes (LLM judges plus heuristics that can't be gamed by keyword stuffing or volume), (b) outcome gaps calibrated to real spreads (e.g. top-quartile vs median reply rates, win rates, CAC, NRR, close times, hire quality), and (c) feedback that teaches what a stellar operator would have done differently. Mediocre play should look plausible but compound into worse outcomes; stellar play still faces luck and base rates. When adding or changing a feature, write down the stellar / good / average / mediocre behaviour and its expected effect size, and add a test that the tiers separate. **The asymmetry is deliberate: good play is necessary but not sufficient, and bad play reliably costs you.** Doing everything right raises your odds but doesn't guarantee a big outcome (market, timing and luck still decide most of it). Doing things wrong must always have realistic consequences: wasted hours and money, slower progress, going in circles (rebuilding, re-pitching, re-hiring, re-launching), burned lists and domains, churned customers, damaged reputation, legal or tax bills, burnout. Some come immediately; many compound or surface weeks later, as in real life. A mistake should never be free, and its cost should be traceable afterwards (Scorecard, coaching, post-mortem).
8. **Works offline.** Every LLM call supplies a deterministic heuristic `fallback`. Results are flagged `mock` and the UI says "offline".

## App module contract

```js
export default {
  id: 'crm', title: 'CRM', icon: '🗂️', group: 'Sales',
  models: ['smb', 'ent'],          // optional: only show for these business models
  badge: (state) => 3,             // optional sidebar badge
  render(root, ctx) {},            // draw into root (use mount + html``), wire events with on(root, ...)
  onDay(state) {},                 // optional: synchronous daily simulation (no awaits, no DOM)
  onMonthEnd(state) {},            // optional
  jobs: { 'reply:prospect': async (ctx, payload, job) => {} }, // optional async (LLM) handlers
};
```

`ctx` (in render and jobs): `state`, `params` (route string after `#/id/`), `act(fn, {hours, label})`, `save()`, `render()`, `navigate(appId, params)`, `enqueue(type, payload, {label})`, `llm` (core/llm.js module), `toast`.

Rules:
- `render(root, ctx)` is called on every state change with a **fresh** `root` element (the shell creates a new one each time), so it is safe to attach listeners with `on(root, ...)` inside render; they are discarded with the old element. Keep render fast. Charts: draw after mount (canvas inside root). Note re-render replaces inputs, so keep in-progress text in state or a module-level draft variable if an action can re-render mid-typing.
- `onDay(state)` must be synchronous and deterministic given `state.seed` (use `rng(state)` / `chance` / `poisson`, never `Math.random`).
- Enqueue LLM work from `onDay` with `enqueue(state, type, payload)` imported from `core/jobs.js` (the shell runs jobs after the tick). From UI actions use `ctx.enqueue` or await `ctx.llm.ask/panel` directly inside `ctx.act`.
- Money only moves through `bank.post` (bank) and `core/stripe.js` (customer payments). Use correct categories (`advertising`, `marketing`, `payroll`, `payroll_tax`, `contractors`, `software`, `ai_inference`, `hosting`, `legal`, `accounting`, `taxes`, `investment`, `loan`, `loan_repayment`, `owner_contribution`, ...).
- New paying customers: `createCustomer` + `subscribe(state, customerId, plan, { trial, source })`. `source` is a channel string used for attribution: `ads:meta`, `ads:google`, `ads:tiktok`, `ads:apple`, `organic:seo`, `organic:social`, `organic:community`, `network`, `referral`, `outbound`, `inbound`, `partner`, `product-hunt`. B2B deals won in the CRM pass `crmCompanyId` to `createCustomer`.
- Never edit files you don't own. If you need a core change, write it in your final report.
- Escape everything: always render untrusted text through `html``…```.
- Mobile: layouts must work at 390px wide (use the grid classes; they collapse).

## Cross-app hooks (use these instead of reaching into other apps)

- Operator tiers and mistakes: `core/operator.js` (see Files). Every function registers a reader; every consequential mistake calls `logMistake` with a cost so the Scorecard can show what it cost and which events were "going in circles".
- Automations: apps export `*Events(state, sinceDay)` (stable event ids) and action functions that support `{ dryRun }` and return `{ ok, error, hoursCost, usdCost }`; anything customer-facing requires `approved: true`. Hours an automation really saves are claimed with `claimAutomated(state, key, hours)` from `apps/automations/engine.js` (catch-up hours are charged later if a run fails).
- Founder assistant: `claimAssistant(state, key, hours)` (apps/assistant) for approved digests, investor updates and meeting prep.
- Focus: charge writing work through `writingHours(state, h)` and build work through `deepWork` (core/calendar.js).
- Runway: `runwayMonthsForecast(state)` (apps/money/common.js) is the line-item forecast other apps read.
- Activation: `activationLift(state)` from apps/insights/model.js (registered by Insights; Lifecycle email + onboarding experiments).

## Formal RFPs (sales/rfp.js, sales/rfp-view.js, CRM -> Bids)

A deal whose procurement plan needs an RFP (`deal.proc.rfp`, owner-led deals only) or an unsolicited public bid (after registering on bid portals) becomes a `crm.rfp.bids` record that the player works through; the flat `rfpMult` applies only to deals that never entered the process. Stages: `issued` (go/no-go checklist, optional call to the buyer) -> `bidding` (Q&A before the question deadline, addenda that must be acknowledged, forms, compliance matrix checked against shipped Product features, security questionnaire, price, references, executive summary, compliance check, submit) -> `submitted` -> screening (pass/fail, forms, page limit, late) -> weighted evaluation against a hidden field (wired bids capped) -> `shortlisted` (demo/orals as a calendar meeting) -> optional `bafo` -> notice of intent, protest window, negotiation, council/board vote -> the deal's own `sendContract`/`closeWon` path. Losses open a 3-day debrief window and an optional protest (~14% sustain base rate). Cooperative contracts (NASPO/Sourcewell/OMNIA style) are a months-long application that lets buyers skip their RFP (`paperAssets.coop_contract`) for an admin fee.
- Truth sources: hidden `bid.wired`, `bid.budget`, `bid.weights`; the matrix is compared with `state.apps.product.features` and Legal/credentials at submission and again at implementation kickoff (`overclaimed_compliance`, delayed, with credits, rework hours, possible termination and claim).
- Actions record `bid.hoursSpent`; the UI charges the same hours with `ctx.act`. Mistake ids: `bid_on_wired_rfp`, `overclaimed_compliance`, `false_certification_claim`, `disqualified_missing_form`, `disqualified_mandatory_requirement`, `late_submission`, `boilerplate_response`, `bafo_below_cost`, `no_debrief_requested`, `repeated_rfp_loss` (circles), `protest_without_basis`.
- Operator reader `rfp_bids` (data/operator-tiers.js): go/no-go discipline against the hidden truth, win rate on bids taken, matrix honesty, disqualifications, debrief use, wasted hours, process habits. Test: test/rfp.test.js (scripted stellar/good/average/mediocre on the same six bids).
- Events (`rfp_issued`, `rfp_question_deadline`, `rfp_due_soon`, `rfp_addendum_issued`, `rfp_shortlisted`, `rfp_awarded`, `rfp_lost`) and actions (`rfp_no_bid`, `rfp_request_debrief`, both approval-gated) are in the Automations catalog. Research: docs/research/rfp/. Numbers marked [design] are assumptions.

## GTM compensation, GTM roles and land and expand

Research: docs/research/gtm-comp/ (comp-plans.md, land-and-expand.md). Data and every [design] number: `public/data/gtm-comp.js`.

- **Roles.** `csm`, `am`, `se` and `founding_ae` are People job roles (catalog.js, data/roles.js incl. interview material and candidate pools). Member roles `csm|am|se` join `ae|sdr`; `founding_ae` is an `ae` with `jobRole: 'founding_ae'`.
- **Comp plans** (`people/comp.js`, UI People -> Comp plans, `people/views-comp.js`): one plan per role in `state.apps.people.comp.plans` (OTE, base share, pay metric, quota, rate override, accelerators, decelerator, cap, clawback, draw, pay timing, founder-credit, discount authority, SPIFF). Pure math: `payoutFor`, `settleDraw`, `clawbackFor`. `compDay` turns won deals into credits (`comp.credits`) and applies clawbacks; `compMonthEnd` settles at the period end into `member.commissionDue`, which the existing payroll run pays (`payroll.js`, separate COMMISSIONS line, category `payroll`). Variable pay is no longer a flat share of new ARR or paid at target. `repMods(state, m)` feeds `salesCapacity` and the sales engine (SDR meetings/qualified ratio, AE win rate and discount, sandbagging via `sandbagHold`, poor-fit closes via `sub.poorFit`/`sub.gtmChurnMult`, booking-pay collections via `sub.nonPayMult`). `member.compAttr` and `member.compMoraleDrag` carry attrition and morale effects. Mistakes use functionId `gtm_comp_design`: `comp_pays_for_junk_meetings`, `no_clawback_bad_fit_churn`, `capped_plan_sandbagging`, `midyear_plan_change`, `confusing_plan`, `ote_below_market`, `ote_above_market`, `quarter_end_discounting`.
- **CSM / AM / SE** (`people/gtm-team.js`): `assignOwners` assigns CSMs (all accounts) and AMs (mid-market and up) by capacity (accounts per CSM ~110 SMB / 35 mid / 10 enterprise, [unverified]); an overloaded CSM loses effect (load^-1.3). Effects are stored on `acct.gtm` (`ownerChurn`, `healthBonus`, `renewalBonus`) and read by the success engine. `seEffect` raises win rate and shortens cycles on deals of $25k+.
- **Land and expand** (`sales/expand-model.js` pure, `sales/expand.js` simulation, `sales/expand-view.js` UI in Success -> Land & expand and the account page): the land strategy is chosen per deal in the CRM proposal (`deal.land`, applied in `startProposal`); each Success account gets `acct.land`, `acct.map` (hidden whitespace by department, threads, exec sponsor), `acct.adoption`, signals, ramped contracts, paid-pilot conversion and true-ups. Expansion and contraction call `changePrice` (quantity/price), so Stripe shows expansion/contraction MRR events. `acct.gtm` factors (champion risk, ignored renewal, upsell before value, land fit) multiply into `csChurnMult`. Mistakes use functionId `account_expansion`: `upsell_before_value`, `anchored_low_price`, `over_discounted_land`, `oversized_land_shelfware`, `single_threaded_account`, `no_account_owner`. Calibration targets: `NRR_BANDS` (median operator inside the band, tested on one year of 4 seeds x 22 accounts).
- **Operator tiers:** `gtm_comp_design` (reader `people/comp-readers.js`) and `account_expansion` (reader `sales/expand-readers.js`). **Automations:** people triggers `comp_paid`, `rep_hit_cap`, `clawback_triggered` (`PEOPLE_TRIGGERS`); sales events `expansion_signal`, `renewal_due`, `champion_left`, `account_contracted` (`SALES_NEW_EVENT_TYPES`). Tests: test/comp-expand.test.js (helper test/helpers/gtm-cohort.js).

## Global and part-time hiring

Research: docs/research/hiring-global/international-part-time.md. Data and every [design] number: `public/data/regions.js`; logic: `people/global.js`; reader `people/global-readers.js`; UI `people/views-global.js`.

- **Regions** (`us, canada, weu, latam, eeu, india, pakistan, ph, africa`): pay as a share of the US range by role class (engineers from Terminal 2026 where sourced, the rest [design]), an EF EPI-shaped English distribution, places with UTC offsets, pool depth, senior share, time-to-fill multiplier, notice period, applicant noise, FX/payout fee, outage risk, holidays, fraud multiplier, misclassification hazard and EOR load. Candidates get their own English level, place, seniority and notice from a per-candidate stream (`streamFor`), never from the name, and these draws do not move the main `rng(state)` sequence the older hiring calibration depends on.
- **Time-zone overlap**: `state.apps.people.global.core` (default US Eastern 9-17, `setCoreHours`). `overlapHours` against a person's workday; `job.requiredOverlap` shrinks the pool (`regionFlow`, `poolShare`) unless `job.allowShift` (they shift their day, +10% night / +5% early-late premium). Effects are applied in one place, `applyOutputMods` (called by `performance.js outputFor`): engineer cycle time and bug rate, customer-facing win/reply/meetings/CSAT/churn, support first-response via `supportCoverage` (handoff runbook `planCoverage`, follow-the-sun), founder coordination hours (`managementHours`), odd-hour calls draining `founder.energy` (`globalWeekly`).
- **English**: `member.english`, `cand.englishLevel` (1-5). Customer-facing roles (AE, SDR, CSM, AM, support, writers) lose reply/conversion/CSAT below "professional"; engineers a small rework penalty. The resume only claims a level; `recordEnglish` reads from the screen call, the interview (tighter with structured probing), written samples, trials. Take-homes with undisclosed AI read better than the person writes.
- **Fraud and J2**: base stand-in share from the role pool, raised by region; overemployed share [design]. Caught by camera-on + ID (`startInterview(..., { camera })`), paid trial, backchannel/references, background check (pro package verifies employment). Missed: output ~30% (stand-in) or ~62% (J2), security incident hazard, mistakes `hired_fraudulent_candidate`, `overemployed_hire`.
- **Part-time**: employees 10-30 h (`part_time_employee`; EOR abroad), contractors 5-40 h, fractional executives 4-20 h (`fractional_cfo|cmo|vp_sales|head_cs`, contractors with `fractional: true`). `partTimeEfficiency` (20 h is ~68% as productive per paid hour [design]), `partTimePremium`, fewer overlap hours (shorter workday), `PART_TIME_FIT` and `loadHours`: a part-time contract for a full-time job raises quit risk and morale drag. ACA 30 h line: US employees under 30 h get no health plan (`employerAnnual(state, gross, { hours })`).
- **Legal/admin**: EOR load by region + Deel fee, FX/payout fee posted to the ledger on contractor invoices and EOR payroll (`postFxFee`, runway includes it), Contractor of Record, `misclassified_foreign_contractor` (logged at start for staff-like work, reclassification claim later), `no_ip_assignment_contractor` and a local-law IP assignment (`offer.localIp`, once per country; `legalIssues` flags foreign contractors without it for investor diligence).
- **Mistakes** use functionId `global_hiring`: `low_overlap_customer_role`, `english_mismatch_customer_facing`, `hired_fraudulent_candidate`, `overemployed_hire`, `misclassified_foreign_contractor`, `no_ip_assignment_contractor`, `part_time_full_time_job`. Operator reader `global_hiring` scores role-to-region match, English assessment, vetting, overlap planning, paper hygiene and part-time fit from `member.vetting` and the hire itself. Test: test/global-hiring.test.js (scripted stellar/good/average/mediocre through the real pipeline; each mechanic one short test).

## AI costs, startup credits and spec autofill (apps/aicost/*)

Research: docs/research/ops-2026/llm-spend.md, startup-credits.md. Data and every [design] number: `public/data/ai-costs.js`, `public/data/credit-programs.js`. State: `state.apps.aicost` (coding, inf) and `state.apps.perks` (applications, credits, cloud), both on a dedicated seeded stream (`aiRng`, `hashU`) so the main `rng(state)` sequence is untouched. Hooks: `aiDay` / `aiMonthEnd` (aicost/index.js) are called from `product.js` onDay / onMonthEnd; `aiEvents(state, since)` feeds Automations (family `aicost`: `ai_spend_spike`, `ai_budget_exceeded`, `credits_expiring`, `credits_exhausted`, `model_deprecation_notice`, `credit_application_approved`).

- **Coding spend** (coding.js): each active People engineer (read only) takes a seat (individual, plus, power, team standard/premium) plus pay-as-you-go API for agentic work. Per-engineer usage is log-normal (heavy tail past $1,000-5,000), limits slow the team (`codingLimitFactor`, applied in `velocity()`), seats post as `software` and API overage as `software` (R&D, not COGS). Incidents: runaway agent loop, leaked shared key. Mistakes: `unmonitored_agent_spend`, `shared_api_key_leak`, `no_spend_alerts`.
- **In-product inference** (inference.js): shipped features with `ai.enabled` generate requests per active user (chat / RAG / agent / extraction token profiles); the model tier (frontier / mid / small), prompt or aggressive caching, batch, routing, per-user caps, free tier and its abuse set the monthly `ai_inference` COGS bill (replaces the legacy `AI_LEVELS` accrual once an AI feature is live). Quality is hidden; a cheaper setup without a prior `runEval` drops it below the baseline users adopted, which raises churn and lowers conversion (`ai-quality` modifiers). Model retirement notices force a migration. Pass-through: included credits + paid top-ups or an AI add-on, charged through Stripe. Mistakes: `negative_margin_ai_users`, `free_tier_abuse`, `model_swap_without_evals`, `no_rate_limits`, `model_deprecation_ignored`. UI: Product -> AI costs.
- **Credits and perks** (credits.js, Bank -> Perks & credits): programs with tiers, routes (self / referral / accelerator / VC), a public eligibility checklist (read-only checks against the fundraising slice, domain, website, LinkedIn, allocations), hours, delays and a deterministic approval roll. Approved credits are balances; `core/bank.js` `setCreditOffsetHook` routes a matching charge through the ledger before cash, so cash moves by the NET amount, `meta.gross` / `meta.creditApplied` keep the invoice (contra-expense, never income; unused credits are not cash or runway). `cliffSchedule` feeds `money/forecast.js` line items. Cloud footprint and provider lock-in are modelled (`moveCloud`, `setFootprint`). Mistakes (function `startup_perks`): `applied_ineligible`, `credit_cliff_surprise`, `overprovisioned_on_credits`.
- **Spec autofill** (autofill.js, Product spec editor): drafts only from gathered evidence (real insights, interviews, tickets, feature requests, churn reasons, experiment learnings), cites it, costs 0.2 h; thin evidence gives a generic draft that `lintSpec` still blocks; an unedited draft is capped at 14/20; repeated no-evidence autofill logs `autofilled_generic_specs` (function `product_prioritization`) and weak specs queue with +25% effort.
- **Operator tiers**: `ai_cost_management` and `startup_perks` (readers in aicost/readers.js). Tests: test/ai-costs-credits.test.js.

## People ops: negotiation, onboarding, benefits and time off, workplace

Research: docs/research/ops-2026/{negotiation-onboarding,benefits-time-off,office-remote}.md. Data and every [design] number: `public/apps/people/ops-data.js`; state: `state.apps.people.ops` (`ops-state.js`); hooks called from sim.js: `people/ops.js`. All randomness uses per-candidate and per-member streams (`streamFor`), never `rng(state)`, so existing seeded flows are unchanged.

- **Negotiation** (`negotiation.js`). After an offer a candidate may counter (salary, equity, sign-on, start date, remote); some hold a competing offer or an employer counteroffer. Actions: `acceptCounter`, `counterBack`, `presentMenu` (cash vs equity), `addSignOn`, `setDeadline`, `walkAway`, `raiseSalary`. Engine interface for a shared negotiation engine: `candidateReservation(state, c)` (hidden min base, equity appetite, competing-offer strength, deadline) and `applyAgreedPackage(state, candId, pkg)`. Consequences: lowball -> accepted but higher attrition and morale drag; overpay -> pay-equity hit on the team; exploding offer vs a rival -> candidate lost; unanswered counter expires; renege before day one; no pay range in CA/CO/NY/WA/EU -> fine risk. Mistakes: `lowball_offer_attrition`, `exploding_offer_lost_candidate`, `pay_inequity_team`, `no_salary_range_posted`, `negotiation_stalled`, `offer_reneged`.
- **Onboarding** (`onboarding.js`). Per-hire checklist (`m.onboarding`): welcome call, laptop, accounts, I-9 (US, 3 business days), 30/60/90 plan (manage.js), buddy, calendar meetings. Quality sets ramp weeks (AI-tool effect for engineers) and the 90-day exit hazard (~25% unstructured vs ~6% structured, [design] on a sourced 28-33% baseline). Offboarding: access removal. Mistakes: `no_onboarding_plan`, `missed_i9_deadline`, `access_not_revoked`.
- **Benefits and time off** (`benefits.js`, `absence.js`). Policy drives payroll burden once configured (`catalog.js benefitsFor`): KFF 2025 premiums trended by 2026, QSEHRA 2026 caps, PEO PEPM, dental/vision, 401(k) fee and match, stipends. PTO accrued/unlimited/statutory; accrued balance is a liability and is paid out at exit in CA; state sick-leave mandates; EOR statutory leave. Absence simulation: vacation requests (approve/deny), heavy-tailed sick days, medical, burnout, parental and bereavement leave; `presenceFactor` feeds capacity.js; coverage gaps for single-person roles. Mistakes: `no_health_benefits_lost_candidate`, `pto_payout_owed`, `denied_vacation_burnout`, `single_point_of_failure`, `state_sick_leave_gap`.
- **Workplace** (`workplace.js`). Remote, coworking, lease, hybrid; rent via `addRecurring`. Effects: applicant pool for office-required roles (`regionFlow`), city salary asks, quits by mode, junior in-person edge, solo-founder isolation, offsites. Mistakes: `long_lease_too_early`, `personal_guarantee_called`, `office_required_shrinks_pool`.

## Negotiation engine (core/negotiation.js, apps/negotiate/*, apps/negotiate-view.js)

Research: docs/research/negotiation/science-and-enterprise.md, vc-terms.md. Data and every [design] number: `public/data/negotiation.js`. State: `state.apps.negotiation` { items, events }. One engine, many adapters.

- **Engine.** A negotiation has a counterparty persona (role, style `hardball | collaborative | time_pressed | bureaucratic`, hidden BATNA strength, reservation, priority weights, per-issue floors, deadline, patience, trust) and issues (numeric ranges or option sets with a player utility and a counterparty utility). The player sends a package offer plus an optional message and three statements the counterparty reacts to (a real alternative, a walk-away, splitting the difference). `playRound` uses the LLM persona when a key is present (hidden values in the prompt, JSON back) and the deterministic offline model otherwise (`playRoundSync`). Every LLM reply goes through `validateReply`: it can never accept or counter below the hidden reservation or floors, an unjustified walk is refused, hidden numbers are scrubbed from the message. Randomness is a dedicated seeded stream per negotiation (`neg.rs`); the main `rng(state)` is untouched.
- **Offline dynamics.** Anchoring (the first offer pulls their target; a precise number pulls harder; an offer far beyond their zone costs trust and can end the talks), diminishing concessions, reciprocity (a large unreciprocated concession is pocketed), logrolling (concede what they value and you do not, hold what you value; arithmetic on the hidden weights, no keywords), deadlines (theirs pull them toward the reservation, yours, once they know it, slow them), credible walk-away and leverage (only as real as the BATNA the adapter reads from game state: competing term sheets, other pipeline deals, other offers), bluffs (an invented alternative is checked: trust collapses and a mistake is logged now or at signing), splitting the difference, impasse. Founder hours: a round is 0.25 / 0.5 / 1 h by stakes; each Prepare step (alternatives, market norms, research the other side in two depths) costs hours and reveals only what it researched.
- **Scoring.** At close: surplus captured (player utility above the real alternative over the best attainable given the hidden zone), joint-value efficiency (distance from the frontier at the same cost to the other side), value left on the table, and a debrief of what a stellar negotiator would have done. Operator reader `negotiation` (data/operator-tiers.js): surplus, joint value, preparation, concession discipline, integrity, walk discipline. Tests: test/negotiation.test.js with scripted negotiators (test/helpers/negotiators.js).
- **Adapters** register with `registerAdapter(kind, { batna, onClose })`: `enterprise` (CRM contract stage; terms land on the deal, Stripe subscription and first invoice, Legal exposure; consequences.js: net-90 delays cash, uplift cap limits Success renewals, MFN reprices a customer when a deeper discount is given later, uncapped liability pays a claim in full, termination for convenience churns, `caved_on_discount`, `no_give_get`, `quarter_end_desperation_discount`, `uncapped_liability_signed`, `mfn_triggered_repricing`); `vc` (term sheets and SAFEs; exploding offers allow no negotiation, a real second term sheet lifts the valuation 5-15% on top of a few percent of room; preference and participation reach the cap table and `waterfall`, governance and vesting reach the exit; `accepted_participating_pref`, `pool_shuffle_ignored`, `gave_up_board_control`, `bluffed_competing_term_sheet`, `overplayed_hand_lost_term_sheet`); `mna` (acquisition LOIs; holdback released net of a possible claim, stock at a haircut, earnout from the MRR trajectory, longer exclusivity raises retrade risk; `long_exclusivity_retrade`, `earnout_heavy_deal`). `others.js` exports `vendorSpec/startVendorNegotiation` and `hiringSpec/startHiringNegotiation` factories plus `registerClose(kind, fn)`: wiring them into Money (vendor invoices) and People (offers; wrap people/negotiation.js `packageValue`) is TODO for the coordinator, neither app is edited here.
- **Hooks.** sales/model.js closeWon applies negotiated terms; sales/engine.js contractDay holds signature while a negotiation is open; success/engine.js proposeRenewal honours the uplift cap; fundraising/sim.js issues term sheets with full detail (negotiate/vc-terms.js), writes preference and governance when a priced round closes, and settles LOIs (negotiate/mna-terms.js); captable.js `waterfall` supports participating preferred; crm.js onDay calls `negotiationDay` (expiry and delayed consequences). Automations: family `negotiation` (`negotiation_started`, `counteroffer_received`, `negotiation_closed`, `negotiation_walked`).
- **UI.** `negotiate-view.js` exports `negotiationLauncher`, `negotiationPanel`, `wireNegotiation`: offer form per issue, message box, timeline, mood/trust, Prepare panel, post-close debrief. Mounted in the CRM deal panel (contract stage), the Fundraising investor panel (term sheet) and Exit offers.

## LLM usage pattern (see apps/website.js)

```js
const res = await ctx.llm.panel({
  task: 'cold_email_reply',                 // stable name, used for caching and fallback logging
  system: `${REALISM}\nYou are ${persona}…`,  // REALISM keeps personas skeptical and terse
  prompt: '…the actual artifact to judge…',
  schema: { type: 'object', additionalProperties: false, required: [...], properties: {...} }, // strict JSON schema
  fallback: () => heuristic(...),           // deterministic, same shape as schema
  cache: state.cache,                       // optional: identical inputs reuse results
});
// res = [{ data, mock, model, usd }, …] — one per chat model (default Claude Haiku 5.5). Pass `rubric` (core/rubric.js criteria)
// and Jev also scores each criterion; numeric criterion fields become the mean of the chat score and Jev's.
```

Give every judge and role-play the business it is about with `context: bizBlock(ctx.state, level)` (apps/context.js), at the level that person could know: `'public'` (one-liner, website, public pricing), `'customer'` (+ they use the product), `'insider'` (+ ICP, traction, cash, team; for your assistant, team, investors with info rights and graders of your own work). Cold prospects, interviewees and strangers judging an email or post get none: they only see what is in front of them.

**Jev is for typed decisions only.** `ctx.llm.decide({ task, state, questions, fallback })` asks TypeSafe's Jev (System One model, `LLM.decisionModel`) `choice` / `noul` (yes-no) / `score` (ordered scale) questions and returns probabilities and confidence, never text. Use it wherever code acts on a label, a yes/no or a level: classification, routing, gating, rubric scores, buy/no-buy. Never give it role-play or prose; chat models write, Jev decides.

Use `ctx.llm.ask` for single-model role-play (e.g. a live chat with a prospect or investor). Keep prompts compact; cap uploaded text. Strict JSON schemas need `additionalProperties: false` and every property listed in `required`.
